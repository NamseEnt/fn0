# Quint-to-Rust Correspondence

The Quint models prove properties of the bounded abstract models, not the Rust
implementation. The correspondence tests exercise concrete Rust executions
against independent reference semantics and the abstraction contracts, reducing—but not
eliminating—the implementation/model correspondence gap.

## Deterministic corpus scope

`formal_correspondence.rs` uses eight fixed seeds and a finite 24-key corpus. It compares every known key including missing revisions, full scans, selected queries, and ordered point-read vectors. It performs deterministic crash/reopen and checkpoint/reopen cycles. The pre-sync fault matrix specifically injects `during_wal_sync` before `sync_data()` is called, then drops volatile file contents with `CrashableFile::crash()`.

This is concrete implementation evidence for these sampled executions, not a Rust correctness proof and not an exploration of every storage state. `durability_dst.rs` adds deterministic exploration of the following concrete cases:

- Every byte prefix from the durable INIT boundary through the complete unsynced WAL stream for one physical group containing logical `Put A` and `Put B` commits. Torn final frames reopen safely; committed recovery is only `[]`, `[A]`, or `[A, B]`, never `[B]`.
- WAL scanning retains complete but uncommitted frames in `next_lsn`; observed `next_lsn` is monotonic through the prefix sweep and `history_start_lsn` stays at the initial checkpoint boundary.
- A `sync_data()` error is tested with none, partial (A-only), and all group bytes persisted. The returned operation is an error in all cases, while reopen reflects the persisted logical commit prefix.
- Each named checkpoint fault point is crossed with available durable and volatile whole-file images for both data and WAL files. Recovery preserves exact values and revisions, invariants, and the next revision floor.
- Every byte prefix of a new WAL reset INIT frame is reopened against the durable checkpointed data image, including the empty-WAL and torn-INIT recovery paths.

The data-file candidates are limited to the last synced durable image and the current complete volatile image. Whole-file byte-prefix truncation is used only for append-only WAL streams; it is not a model for data-file page overwrites. Existing short-write and recovery tests cover selected partial page writes separately.

This deterministic schedule exploration covers WAL persisted-byte positions, sync-error persistence outcomes, and named checkpoint operation points crossed with durable/volatile file-image choices. It does not enumerate thread scheduler interleavings. Remaining gaps include:

- Arbitrary sector or block reordering inside the data file.
- Arbitrary partial overwrite persistence of data pages.
- Real filesystem, kernel, or controller power-loss behavior.
- Hardware torn-write guarantees.
- All concurrent thread scheduler interleavings.
- Every possible workload or page-layout history.

These tests do not prove production Rust correctness.
