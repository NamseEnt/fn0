# Direct immutable-base recovery and bounded checkpoint sync

The existing version-3 manifest and immutable-pack format are unchanged. Manifest-listed packs and required committed WAL remain the sole authority. The mutable database file is disposable for this layout; neither its contents nor its length proves checkpoint coverage.

Recovery validates pack identities, complete allocated-page coverage, checksums, WAL continuity, exact delta bases and commit boundaries as before. It builds the tree directly from the resulting page images and manifest-selected metadata, with newer committed superblock images supplying post-checkpoint root/free-list/high-water changes. It checks superblock identity, decodes each allocated page, rejects missing or out-of-range images, constructs the existing generation publisher and checks tree invariants. A newly created, never-mutated database has the canonical empty root. Replayed pages newer than the manifest checkpoint remain dirty until a later checkpoint publishes them. Successful recovery must accept an acknowledged mutation and survive another recovery.

A full checkpoint captures immutable references for clean decoded pages, together with the already encoded dirty images, at a fixed committed target. The worker encodes these captured pages. Later mutations use the existing copy-on-write page ownership; they cannot change the captured generation. The retained snapshot and disk reservations still count every captured page, including those awaiting encoding.

During pack creation, each 8 MiB of page output is synchronized before more output is written. Intermediate file synchronization does not publish the pack and does not authorize reclamation. An interrupted or failed partial file remains an unlisted orphan. The final whole-pack checksum and final file sync, pack-directory sync, latest-manifest atomic publication and directory sync, covered-file unlink and reclamation-directory sync retain their original ordering. Failure before or after intermediate sync must recover from the old manifest and retained WAL. Failure after durable publication must recover from the published pack and post-target WAL, including acknowledged writes made during background execution.

Ordinary segmented and legacy WAL retain their existing recovery and checkpoint behavior. Existing databases never convert implicitly. Process-crash and modeled I/O-failure tests do not constitute arbitrary physical power-loss testing.
