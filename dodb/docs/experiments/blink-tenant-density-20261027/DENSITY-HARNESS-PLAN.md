- Add a dedicated `tenant_density_workload` binary, with supporting modules under its bin support directory as needed, instead of changing the 3,590-line historical `service_workload` schedule and oracle.
- Reuse `MemoryDiagnosticSession`, `MemoryDiagnosticWorker`, `RemoteDodbService`, their loopback TLS transport, PID/start-time identity checks, binary hashes, phase sampling, and termination handling. Both measured backends use this identical transport/executor topology. Latency includes transport and service runtime; backend-process RSS is not pure engine heap.
- Extend `memory_diagnostic_worker` to instantiate the existing contract-equivalent `MinimalNativeService`; the current driver already sends the name minimal-native, but the worker currently rejects it. Keep reserved-range revisions and exclusive condition locking. Raw WriteBatch is not a comparator.
- Its execute future performs synchronous native work. The new worker route must offload that future to the Tokio blocking pool rather than blocking an async runtime thread. Use the common server in-flight limit and report the blocking adapter explicitly; do not introduce an unreported backend-specific semaphore or change the historical service implementation.
- Reuse the existing checkpoint option parser to forward legacy/segmented/segmented-base/coalesced-base layout, segment size, WAL trigger, and sync/background execution into the B-link worker. Retain legacy/sync/disabled defaults when these flags are absent. Report effective configuration and actual checkpoint metrics; do not label cache_capacity as a B-link memory limit.
- Reuse Linux process/host sampling. The separated-memory diagnostic is Linux-only; local Darwin unit/build checks must not be described as live backend-memory validation. A small Linux end-to-end correctness smoke will be run on the designated host if its live resource checks permit it. No performance ranking is derived from that smoke.

## New harness behavior

1. Strictly validate explicit backend, data/report paths, seed, registered/active/opened-idle tenant counts, client count, duration or finite operation count, initial rows, value bytes, load topology, per-tenant rate, queue bound, in-flight bound, timeout, and checkpoint settings. Reject unknown/duplicate/invalid or incompatible options before spawning a worker or creating databases. Support at least 512 tenant IDs without a fixed 16-open-shard or client-key-space ceiling; compute shard capacity from actual setup requirements.
2. Define registered tenants as the workload's eligible on-disk tenant population, not a new service registration API. Seed the population in a setup worker, stop it, and use a fresh measurement worker that opens only active tenants and explicitly opened-idle tenants. Registered-but-never-opened must mean never opened in the measurement worker epoch. Validate active + opened-idle <= registered. All-active is registered=active. Expose per-phase and worker epoch accounting.
3. Use 16-byte PK and 16-byte SK, at least 256 rows per partition, and Query requests that actually return 16 rows. Report canonical key lengths and actual rows per Query. Values are configurable, with 512-byte default and 4096-byte support. Compute seeded values from tenant/key/seed so the oracle need not retain full value payloads.
4. Provide read-heavy (Get/Query/write 80/15/5), mixed (40/20/40), and write-heavy (10/10/80) profiles. Within writes, half are conditional and half unconditional; conditional requests use Exists/NotExists consistently with the acknowledged lane state. Support width 1/4/16 at 80/15/5 and 10% Delete mutations, with actual operation/width/condition/delete counts reported. Reserve disjoint key lanes per logical stream and serialize each lane's requests so acknowledged-state validation is deterministic without serializing all tenants in a parent lock. Include a separate correctness check for revision conditions, intended rejection, multi-key atomicity, and tombstone/reinsert behavior; the initial timed schedule must accurately state its actual conditions rather than imply it already includes every PLAN.md variant.
5. Fixed-total topology uses a configured fixed number of sequential logical streams multiplexing every active tenant. Fixed-per-tenant topology schedules arrivals independently of completion, using explicit scheduled deadlines and bounded queues. Include queueing in scheduled-to-completion latency. Never await a full queue in the arrival producer, create an unbounded task list, reset arrivals to completion times, or silently discard backlog. Record scheduled, admitted, completed, successful, conflicting/rejected, dropped, timed-out, and queued/in-flight counts per tenant. Report offered-window completion separately from drain completion, queue high-water, and final backlog. Do not call an ever-growing or dropped workload stable capacity.
6. Treat timeout/cancellation of a mutation as an uncertain outcome: retain artifacts, mark the cell invalid/inconclusive, and do not silently update the oracle as though the mutation was rejected. On all paths, terminate/reap workers and bound drain. A failure report should retain partial counters and a reason; never delete a failed database to obtain a clean rerun.
7. Record total and per-tenant operation latency with bounded histograms or equivalent bounded summaries whose counts cover all requests. Record deterministic schedule/input fingerprints with operation counts so matched prefixes can be compared without treating unequal completed workloads as identical. Maintain a bounded key-state oracle; validate every tenant's final acknowledged state and validate it again after a clean worker reopen. Keep seed/open/reopen/oracle timing separate from the offered-load window.
8. Report driver and backend PID/start-time identities, RSS/PSS/anonymous/swap samples and gaps/truncation separately, configured concurrency and actual worker configuration, per-phase file logical bytes and allocated blocks, and checkpoint metrics. Use available process I/O and host/ARC/device counters where accurately supported. Unavailable metrics, including allocator retained heap and representation-specific retained bytes, must be explicit null/unsupported with a reason; they must not become zero or an enforced budget claim. Filesystem allocated blocks are not ZFS dataset/device write amplification.
